เอกสารขั้นตอนการทำงานระบบปลดระวาง IOC (MISP IOC Retirement Workflow)

เอกสารแสดงขั้นตอนการทำงานและสถาปัตยกรรมของสคริปต์ misp_ioc_retirement.py สำหรับนำเสนอหรือใช้งานอ้างอิงในการปฏิบัติงาน

หลักการสำคัญ: สคริปต์นี้จะไม่ปลดระวาง IOC สุ่มสี่สุ่มห้าตามอายุเท่านั้น แต่จะนำ IOC ที่หมดอายุไปตรวจสอบซ้ำ (Enrichment Re-validation) กับฐานข้อมูล Threat Intelligence ภายนอกก่อนเสมอ หากระบบภายนอกล่มหรือไม่สามารถติดต่อได้ จะใช้หลักการ Safety-Fail (คงสถานะไว้) เพื่อความมั่นคงปลอดภัยสูงสุด

2. เกณฑ์อายุของ IOC (Tiered Age Thresholds)

หมวดหมู่ Attribute Types เกณฑ์อายุ เหตุผล
IP ip-src, ip-dst, ip-src|port, ip-dst|port 30 วัน IP มีอัตราการหมุนเวียนและเปลี่ยนเจ้าของบ่อย
Domain domain, hostname, domain|ip 90 วัน โดเมนของผู้โจมตีมักถูกยึดหรือละทิ้งหลังสิ้นสุดแคมเปญ
URL url, uri 90 วัน Phishing link หรือ C2 endpoint มักถูกปิดตัวอย่างรวดเร็ว
Hash md5, sha1, sha256, sha512 ฯลฯ 180 วัน มัลแวร์ Hash ไม่เปลี่ยนแปลง แต่อายุ 180 วันช่วยลดภาระ Feed ปลายทาง

3. ลำดับการตรวจสอบ Threat Intelligence

  1. Provider A API: ตรวจสอบ IP, Domain, URL, SHA256 (เร็วและครอบคลุมที่สุด หากพบว่ามีความเสี่ยง malicious_score > 0 จะ KEEP ทันที)
  2. Provider B API: ตรวจสอบเฉพาะ URL (หากสถานะเป็น online จะ KEEP ทันที)
  3. Provider C API: ตรวจสอบเฉพาะ File Hash (หากพบตัวอย่างจะ KEEP ทันที)
  4. Provider D API: ตรวจสอบทุกประเภท (หากพบ Pulse > 0 จะ KEEP หาก 404 จะ RETIRE)

4. ผลลัพธ์และการดำเนินการ

ผลการประเมิน สถานะ การดำเนินการใน MISP
ยังพบความเคลื่อนไหวใน Threat Intel KEEP ไม่เปลี่ยนแปลง คงสถานะ to_ids = True ไว้ใช้งานต่อ
API Error / Timeout / Rate Limit SAFETY KEEP คงสถานะไว้เพื่อความปลอดภัย ไม่ปลดระวางผิดพลาด
ไม่พบความเคลื่อนไหว (Offline / Benign / 404) RETIRE Soft-disable: ปรับ to_ids = False และ Republish Event
อยู่ในรายการ Whitelist WHITELIST ปรับ to_ids = False หรือลบทิ้งตามที่ตั้งค่า WHITELIST_ACTION
